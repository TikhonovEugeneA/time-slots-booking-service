#### Dockerfile

Dockerfile - предназначен для сборки образа контейнера, следуя инструкциям в нем.

Инструкции:
- FROM: задает базовый образ;
- RUN: выполняет команду и создает слой образа;
- COPY: копирует в контейнер файлы и папки;
- ENTRYPOINT: предоставляет команду с не переопределяемыми аргументами для вызова во время выполнения контейнера;
- CMD: предоставляет команду с переопределяемыми аргументами, которую нужно выполнить, когда контейнер запущен.

Описание специфичных инструкций:
1. ```RUN pip install --no-cache-dir poetry && poetry config virtualenvs.create false``` - устанавливает пакетный менеджер Poetry без кэша, который образуется из-за использования pip для уменьшения создаваемого образа. Указывает poetry, что не требуется создавать виртуальное окружение, потому что контейнер уже является изолированной средой;

2. ```RUN poetry install --no-root --with dev``` - устанавливает зависимости, которые были скопированы в контейнер командой: ```COPY pyproject.toml poetry.lock .\```, не устанавливая корневой пакет проекта, при этом устанавливает dev-зависимости для того, чтобы проверять и тестировать приложение;

3. ```RUN chmod +x /entrypoint.sh``` - указывает, что файл является исполняемым. В нем хранится команда для запуска миграции и ее применении;

4. ```CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]``` - запускает приложение, которое находится по пути `app.main:app` в контейнере по порту 8000. Хост `0.0.0.0` означает, что приложение принимает соединения на всех IP-адресах, которые машина имеет в сети.

#### Docker-compose

Сервисы:
- api;
- db;

атрибуты api:
- container_name;
- build: указывает конфигурацию сборки образа из исходников, иначе как Compose собирает образ, настройки которого находяться в dockerfile;
- restart: определяет политику перезапуска контейнера; 
- env_file: указывает файл с переменными окружения;
- depends_on: определяет порядок запуска / остановки сервисов;
- ports: публикует порты хост:контейнер;
- volumes: монтирует томы в контейнер (на уровне сервиса);

параметры depends_on:
- condition: service_healthy: ждать, пока зависимость не станет healthy;

атрибуты db:
- container_name;
- image: образ для запуска контейнера;
- restart;
- environment: указывает переменные окружения напрямую в файле;
- ports;
- volumes;
- healthcheck: проверяет работоспособность контейнера.

#### Инфраструктура

Слой предназначен для имплементаций работы с внешними системами, например, базы данных, фреймворки и другая низкоуровневая кухня.

В слое инфраструктуры выделены:
- имплементации репозиториев;
- реализация единицы работы;
- схемы базы данных;
- конфигурация и настройки базы данных;

В конфигурации:

Работа с SQLAlchemy в стиле ORM включает в себя несколько ключевых понятий:
- Модели таблиц: 
- Сессии: объекты, через которые осуществляется взаимодействие с базой данных. Они позволяют выполнять запросы и фиксировать изменения;
- Фабрика сессий: шаблон создания сессий. Он используется для управления подключением к базе данных и создания новых сессий по мере необходимости.

Также настройки базы данных поступают из переменных окружения в .env / .env.example

При создании схем для последующей миграции, я подсмотрел особенность использования миксинов. Также с их помощью код схем становиться понятнее. Выделил следующие:
- Base: добавляет id;
- CreatedAtMixin: добавляет created_at с указанием временной зоны;
- MetadataMixin: добавляет json metadata.

Они представляют из себя абстрактные таблицы, которые добавляют к имплементациям соответствующие поля

Связка Mapped и mapped_column() - современный стандарт декларативного описания таблиц в SQLAlchemy 2.0+.

Mapped - современный способ аннотировать типы данных для колонок в моделях SQLAlchemy. Он позволяет более четко указать, что переменнеая представляет собой колонку таблицы в базе данных, делая код более читаемым и понятным. 

mapped_column() - функция, которая используется для создания колонок в моделях SQLAlchemy. Она принимает в качестве аргументов тип данных колонки и дополнительные настройки.

Различия:
- Mapped[...] - указывает Python и линтерам, какой тип данных будет иметь атрибут у объекта после загрузки из базы данных.
- mapped_column(...) - генерирует колонку базы данных и принимает настройки.

Другими словами, если нужно что-то "стандартное", используется чистый Mapped, а если требуется более детальное описание - добавляется mapped_column().

@declared_attr.directive - декоратор, который нужен для конфигурационных атрибутов самой SQLAlchemy, например, __tablename__
